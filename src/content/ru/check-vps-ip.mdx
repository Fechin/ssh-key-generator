# Как узнать внешний IP VPS после входа по SSH

<img src="/images/articles/check-vps-ip.webp" alt="Терминал SSH на VPS с командой curl myip.dog и примером внешнего IP-адреса" width="1536" height="1024" className="w-full h-auto rounded-xl border border-border" />

*Авторская иллюстрация. На изображении указан пример адреса.*

Вы подключились к VPS по [SSH](/ru/ssh-command/) и хотите узнать, с какого адреса сервер выходит в интернет. Выполните `curl myip.dog` в удалённом терминале. Это быстрый способ проверить внешний IP VPS при диагностике сети или подготовке обращения в поддержку, не открывая панель хостинга.

## Выполните команду именно на VPS

Убедитесь, что терминал находится в SSH-сеансе сервера. Если запустить команду на собственном компьютере, она покажет адрес вашей локальной сети.

```bash
curl myip.dog
```

При успешном запросе вернётся адрес в виде обычного текста:

```text
203.0.113.42
```

Это только пример. Внешний IP VPS нужно брать из фактического ответа в вашем терминале. curl отправляет запрос, а MyIP.dog возвращает адрес источника, который видит при подключении. Отдельный скрипт для проверки не нужен.

Для запроса по зашифрованному соединению HTTPS используйте:

```bash
curl https://myip.dog
```

## Что означает полученный адрес

Результат показывает внешний IP конкретного исходящего запроса. Если сервер использует NAT-шлюз, прокси или VPN, сервис может увидеть адрес этого промежуточного узла. Поэтому он не обязательно совпадает с адресом сетевого интерфейса или адресом для входа по SSH. Команда также не перечисляет все IP, назначенные VPS.

В зависимости от соединения вернётся IPv4 или IPv6. Соответствующие параметры описаны в [документации curl](https://curl.se/docs/manpage.html). Перед настройкой домена на внешний IP VPS уточните у провайдера адрес для входящих подключений и проверьте правила NAT и межсетевого экрана. Успешная проверка IP не означает, что сайт или порт SSH доступны извне.

## Если запрос завершился ошибкой

Сообщение `curl: command not found` означает, что curl нужно установить через менеджер пакетов вашего дистрибутива Linux. При ошибке разрешения имени проверьте DNS. При тайм-ауте проверьте исходящие соединения и настройки прокси. Сохраните точный текст ошибки для дальнейшей диагностики.

## Другие инструменты MyIP.dog

[Главная страница MyIP.dog](https://myip.dog/) показывает внешний IP соединения браузера. Если открыть её на своём компьютере, адрес удалённого VPS автоматически не определяется.

В [каталоге инструментов](https://myip.dog/tools) есть DNS-запросы, проверка IPv6, проверка TCP-портов, Ping, Traceroute, IP WHOIS и калькулятор подсетей. DNS пригодится для проверки записей домена, а проверка портов — для диагностики публичного TCP-сервиса. Онлайн-Ping и Traceroute запускаются с удалённого узла: учитывайте его расположение при чтении результата.

Запишите внешний IP VPS и время проверки. Это поможет сравнить результаты после изменения настроек и передать поддержке понятные данные.
